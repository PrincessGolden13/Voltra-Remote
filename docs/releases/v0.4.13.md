# VOLTRA Remote v0.4.13 — Native Twin controls

This update replaces the blanket Twin read-only path with a supported primary
control profile, following a full comparison with the current native remote repos.

- Resolve the latest scanned Bluetooth address type while preserving saved device
  identity, names and paired navigation.
- Keep an established primary connection through brief status gaps. New loads and
  edits wait for fresh data; explicit unload stays available on the known route.
- Enable supported paired weight/modifier edits while unloaded, explicit load and
  unload, and the existing Auto Load trigger. Use exact paired motor states and
  command words rather than standalone commands or guessed bit masks.
- Allow manual base-weight changes while a loaded pair has fresh stationary
  readings from both cables, with no motor reassertion or accessory changes.
- Send each setting once to the primary in per-unit wire values; show the combined
  amount and its correct adjustment step. Use the primary's current reported limit.
- Decode captured paired motion and rep counts for Live, with the existing clean
  paired names/icons and no extra technical status text.

Secondary/unknown endpoints cannot load the pair. Unknown motor words cannot
authorize loading. Twin Live target resistance is still unavailable: measured
cable force is not substituted. Loaded modifier edits and automatic drops remain
unavailable. Moving or stale cable readings block loaded base edits.

Source, build and offline checks do not prove compatibility with every VOLTRA
firmware. No physical motor operation was performed during development. Saved
Wi-Fi and preferences remain intact; no pairing/unpairing or role changes are sent.

Unload both VOLTRAs and leave the connection, then Settings -> Updates -> CHECK
FOR UPDATES -> INSTALL & RESTART. Keep power connected.
