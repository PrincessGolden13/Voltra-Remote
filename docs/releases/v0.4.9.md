# VOLTRA Remote v0.4.9

- Detect an already-paired Twin using read-only device status; show overlapping
  named circles and combined base/absolute modifier readbacks when pair identity
  and scope are fresh. Percentages stay unchanged; stale/unknown totals are hidden.
- Preserve Twin/readback information when the motor mode is unsupported, rather
  than treating an accepted connection as a blank failed session.
- Permit explicit connection to remembered endpoints that no longer advertise,
  and wait for the previous BLE connection to close before quick reselection.
- Use VOLTRA-reported whole-pound runtime wire load on Live, with BASE separately
  labeled. Missing/stale load shows --; no base/modifier calculation substitutes.
- Retain blocked adjustment and connection reasons in debug reports.

Physical Twin resistance controls are still unavailable: Black's 0xA003 state,
current host/follower role, peer safety and combined limits are not established.
Use the VOLTRAs' controls for Twin load/unload/adjustment. This update does not
guess a role, mask flags, change pairing or send single-unit commands to the pair.
Twin live-load scope and exact agreement with VOLTRA's primary Live LCD require
physical comparison; this is not a claim of complete Twin control support.

For Guition K5 with the existing update layout. Unload both VOLTRAs and leave
Bluetooth, then Settings -> Updates -> CHECK FOR UPDATES -> INSTALL & RESTART.
Keep power connected. Preferences, Wi-Fi and flash layout are unchanged.

Validation: public Normal/isolated Simulator builds, offline core, existing
protocol validators, strict source-fixture inspection, package/image/USB checks
and backend isolation pass. Real LVGL renders cover all three supported sizes.
These are offline checks, not physical Twin control or Live LCD verification.
