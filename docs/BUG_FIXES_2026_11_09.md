# November 9 feedback — v0.4.3 work

## Implemented

- Dim/sleep timing uses a fresh clock after input and synchronous GATT work,
  with a saturating elapsed calculation. Previously an action could set the
  activity timestamp later than the loop's old clock, causing unsigned underflow
  and immediate dim/sleep. Boot initializes the activity timestamp. Zero means
  disabled; first touch/rotary input wakes without performing an action. Loaded,
  armed, pending or unknown connected state keeps unload visible.
- Failed BLE connections get a readable notice explaining that Bluetooth may
  be in use and suggesting disconnection of the phone app and checking proximity.
  Transport failure alone cannot distinguish occupied, off and out-of-range.
- Tapping the VOLTRA name already called leave/disconnect and disabled automatic
  reconnection. That behavior is retained and now logged. It does not claim to
  unload a machine after disconnection.
- Six-second global debug hold, 20-event RAM ring, consent dialog, a durable
  approved report, queued Wi-Fi delivery and reference codes. See DEBUG_REPORTS.md.
  Ordinary long-press actions execute on release; no six-second gesture can
  first trigger Auto Load. The modal retains an unload button while connected.
- UI settings load independently: a damaged preset no longer resets valid
  theme/rest/dim/sleep preferences. Existing schema versions 1 and 2 are retained;
  an unknown future schema is not overwritten by an older firmware's defaults.
  OTA still changes only the inactive application slot and preserves all NVS,
  including Wi-Fi, UI configuration, presets, bootstrap and device memory.
- Safety errors now distinguish absent/stale status from unrecognized numeric
  state and include values/ages in the approved report.

## Not solved by this release

Physical Twin discovery/grouping/control has not been implemented. The existing
physical profile requires standalone state, explaining the current failure.
The reported single-device load failure is not established as fixed: the exact
void-lock comparison remains until the missing decoder or observed value can be
established. See the complete source/revision audit in PROTOCOL_AUDIT_2026_11_09.md.
No guessed peer flags, duplicated commands, lock-mask writes or load retries.
